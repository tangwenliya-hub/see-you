# 小程序体验版上线清单

> 目标：**在微信里扫码就能用**，最多 15 个体验成员，不上架、不做小程序备案、不审服务类目。
> 适用版本：绪见 v1.0（uni-app + Vue3 + SpringBoot）
> 编写日期：2026-11-06

---

## 0. 先认清边界：做什么、不做什么

| 要做 | 说明 |
|---|---|
| 买云服务器 | 后端和数据库要跑在公网上，别人手机才连得上 |
| 买域名 + **ICP 备案** | 微信强制要求：小程序请求的域名必须是已备案域名，IP 和 localhost 一律不通 |
| 配 HTTPS | 微信强制要求 https，且证书必须受信任（自签不行） |
| 部署后端 + 导入数据 | Docker 一键起 MySQL + SpringBoot + Nginx |
| 注册小程序 + 上传体验版 | 个人主体免费，不需要 300 元认证 |
| 添加体验成员 | 最多 15 人，扫码即用 |

| 不用做 | 为什么 |
|---|---|
| 小程序备案（工信部那个"小程序备案"） | 只有**提交审核、正式发布**才需要，体验版不需要 |
| 代码审核、服务类目选择 | 体验版不审核，所以「社交-日记类目个人不开放」这道坎直接绕过去了 |
| 营业执照 / 个体工商户 | 同上，这是正式发布才要的 |
| 微信支付、内容安全检测 | 体验版不涉及 |

**一句话：备案的是"域名"，不是"小程序"。域名备案人人可做、免费、只等时间；小程序备案才卡类目。**

---

## 1. 总时间线

| 阶段 | 事情 | 耗时 | 备注 |
|---|---|---|---|
| ① | 买服务器 + 买域名 + 域名实名 | 1 小时 + 等 1~3 天 | 实名通过才能备案 |
| ② | 提交 ICP 备案 | 提交 1 小时 | **卡点：等 1~20 个工作日** |
| ③ | 部署后端（用 IP 调试） | 半天 | 和 ② **并行做**，不用干等 |
| ④ | 域名解析 + HTTPS 证书 | 半天 | 必须等 ② 通过 |
| ⑤ | 小程序注册 + 上传体验版 | 1 小时 | 可以和 ②③ 并行 |

**关键：②是唯一的等待项。今天买完服务器就能提交备案，然后一边等一边把后端部署好。**

## 2. 阶段一：买服务器和域名（今天就能做完）

### 2.1 云服务器

推荐**轻量应用服务器**（阿里云 / 腾讯云都行），配置要求：

- CPU 内存：**2 核 2G 起步，建议 2 核 4G**。MySQL 8 比较吃内存，2G 需要加 swap（见 3.5）
- 系统：Ubuntu 22.04 / 24.04 或 CentOS Stream 9
- 带宽：3M 以上
- 地域：选离你近的（如华东1/上海）
- **购买时长必须 ≥ 3 个月**，否则不能用来备案。直接买 1 年最省事

买的时候注意两件事：
1. 选**同一家厂商**买服务器和域名，备案系统打通，不用来回填主体信息
2. 记下公网 IP

### 2.2 域名

- 后缀：`.com` 约 60~80 元/年，`.cn` 约 30 元/年（就做体验版，`.cn` 完全够）
- 名字随便，但要**和你的小程序名/备案信息对得上**，比如 `xujian-app.com`
- **域名持有者必须是你本人身份证**，和备案主体一致，否则驳回
- 买完立刻做**域名实名认证**（上传身份证，1~3 天出结果），**实名没通过不能备案**

> 省钱提示：域名和服务器都有新用户首年优惠，别用老账号买。

## 3. 阶段二：ICP 备案（唯一的等待项）

### 3.1 在哪提交

**在你的云厂商的备案系统里提交**（阿里云搜"ICP 备案"、腾讯云搜"网站备案"），不要自己去工信部网站提交——个人直接提交的流程更麻烦，云厂商是代办+初审。

### 3.2 选什么类型

- 备案类型：**新增备案**（首次）
- 备案对象：**网站**（虽然你只用它做小程序后端，但个人只能备"网站"这一类，选这个就对了）
- 网站名称：**填"绪见"两个字最稳**

> ⚠️ 网站名称和服务内容里**不要出现"心理""医疗""健康""咨询""疗愈""诊疗"**这些词。一旦触发，会被要求提供前置审批文件（医疗类资质），个人根本办不下来。写"个人情绪记录工具""随笔记录"是安全的。

### 3.3 要准备的材料

- 身份证正反面照片（清晰、四角完整、别反光）
- 本人手机号 + 邮箱（**手机号不能和已备案过的重复**）
- 人脸核身（手机 App 或小程序里做）
- 按各省要求可能要"幕布拍照"或承诺书
- 服务器 IP（就是你买的这台）

### 3.4 流程五个环节

1. **填信息提交**（1 小时）
2. **平台初审**（1~2 工作日）——期间保持电话畅通，可能打来核验
3. **工信部短信核验**（收到 12381 的短信后**24 小时内**必须去 beian.miit.gov.cn 核验，超时直接驳回，只能重来）
4. **省通信管理局审核**（1~20 工作日，多数地区 3~10 天）
5. **下发备案号**（形如 `苏ICP备2026xxxxxx号-1`），记下来

### 3.5 备案期间的注意事项

- **备案期间域名不要拿来做网站访问**，部分地区会因此驳回。用 IP 调试就行（见第 4 节）
- 服务器**不要关机、不要退订**，管局会抽查
- 备案通过后，域名才能解析到网站；但**解析（A 记录）随时可以加**，不冲突

## 4. 阶段三：部署后端（和备案并行，半天）

备案在等的时候，用**公网 IP 直接访问**把后端跑通。项目里 `deploy/` 已经写好了 Docker 编排，照抄命令即可。

### 4.1 登录服务器装 Docker

```bash
ssh root@你的服务器IP

# 装 Docker（国内用阿里云镜像源，快很多）
curl -fsSL https://get.docker.com | bash -s docker --mirror Aliyun
systemctl enable --now docker
docker --version     # 能打印版本就 OK
```

### 4.2 拉代码

```bash
cd /opt
git clone 你的仓库地址 seeyou      # Gitee 地址，或 scp 上传
cd seeyou
```

### 4.3 配置环境变量

```bash
cp .env.example .env
openssl rand -base64 48            # 生成一串随机字符，复制出来当 JWT_SECRET
vi .env
```

`.env` 里要填的：

| 变量 | 怎么填 |
|---|---|
| `DB_PASSWORD` | 自己想一个强密码（后面导数据要用） |
| `MYSQL_ROOT_PASSWORD` | 同上，**两个保持一致最省事** |
| `JWT_SECRET` | 用上面 `openssl` 生成的那串 |
| `AI_API_KEY` | 你本地 application-local.yml 里那个 DeepSeek Key |
| `MAIL_*` | 不填也能跑，只是找回密码的验证码会打进日志 |

其余保持默认。

### 4.4 启动

```bash
docker compose -f deploy/docker-compose.yml up -d --build
# 第一次要构建镜像（拉 Maven、Node 依赖），5~15 分钟，别中断

docker compose -f deploy/docker-compose.yml ps          # 三个容器都 Up
docker compose -f deploy/docker-compose.yml logs -f backend   # 看启动日志，Ctrl+C 退出
```

看到 Spring Boot 的 "Started SeeYouApplication" 就成功了。

> 内存不够会 OOM（容器反复重启）。2G 机器先加 swap：
> ```bash
> fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
> echo '/swapfile none swap sw 0 0' >> /etc/fstab
> free -h    # 确认 Swap 有 2G
> ```

### 4.5 导入数据库

容器起来的 `see_you` 库是空的，要把本地数据搬过去。

**本地导出（Windows）**，命令行或 Navicat 都行：

```bash
# 命令行
mysqldump -uroot -p --default-character-set=utf8mb4 --single-transaction --routines see_you > see_you.sql

# 或者 Navicat：右键 see_you → 转储 SQL 文件 → 结构和数据
```

**上传到服务器**（在你本地电脑执行）：

```bash
scp see_you.sql root@你的服务器IP:/opt/seeyou/
```

**导入**（在服务器执行）：

```bash
docker exec -i seeyou-mysql mysql -uroot -p你的DB_PASSWORD see_you < /opt/seeyou/see_you.sql
```

验证：

```bash
docker exec -it seeyou-mysql mysql -uroot -p你的DB_PASSWORD -e "use see_you; select count(*) from sys_user; select count(*) from psy_diary;"
```

### 4.6 验证后端通不通

先开安全组（云厂商控制台 → 防火墙/安全组）：**只开 22、80、443**。
**不要开 8081 和 3306**——后端只让 nginx 通过内网访问，数据库绝不对公网暴露。

```bash
curl http://你的服务器IP/api/statistics/overview
```

返回 JSON（`{"code":200,...}`）就说明 nginx → 后端 → 数据库整条链路通了。

> 如果返回 502，是后端还没起完或报错了，看 `logs backend`。
> 如果返回 404，说明 nginx 配置没生效，`docker compose ... restart nginx`。

## 5. 阶段四：HTTPS（备案通过后做）

### 5.1 域名解析

云厂商控制台 → 域名 → 解析 → 添加记录：

| 类型 | 主机记录 | 记录值 |
|---|---|---|
| A | `@` | 你的服务器公网 IP |

等 10 分钟左右，`ping 你的域名` 能通就生效了。

### 5.2 申请免费证书

- 阿里云：控制台搜「数字证书管理服务」→ 免费证书 → 申请（DV 单域名，免费额度每年 20 张）
- 腾讯云：控制台搜「SSL 证书」→ 申请免费证书

申请时填你的域名，验证方式选「DNS 验证」（自动加一条解析，最省事）。签发后下载 **Nginx 格式**，得到两个文件：

- `xxx.com.pem`（证书链）
- `xxx.com.key`（私钥）

### 5.3 放到服务器上

```bash
mkdir -p /opt/seeyou/deploy/certs
# 用 scp 把两个文件传进这个目录，并改名成 域名.pem / 域名.key
ls /opt/seeyou/deploy/certs/
```

### 5.4 切换 nginx 到 HTTPS 版

仓库里已经准备好了 `deploy/nginx-ssl.conf`，改三处：

**① 替换域名**（文件里有 3 处 `YOUR_DOMAIN.com`）

```bash
cd /opt/seeyou
sed -i 's/YOUR_DOMAIN.com/你的域名/g' deploy/nginx-ssl.conf
# 证书文件名也要对上，比如 ssl_certificate /etc/nginx/certs/xxx.com.pem
vi deploy/nginx-ssl.conf
```

**② `deploy/Dockerfile.frontend` 改一行**，让镜像用 HTTPS 版配置：

```diff
- COPY deploy/nginx.conf /etc/nginx/conf.d/default.conf
+ COPY deploy/nginx-ssl.conf /etc/nginx/conf.d/default.conf
```

**③ `deploy/docker-compose.yml` 的 nginx 服务加端口和证书挂载**：

```diff
   nginx:
     build:
       context: ..
       dockerfile: deploy/Dockerfile.frontend
     container_name: seeyou-nginx
     restart: unless-stopped
     depends_on:
       - backend
     ports:
       - "80:80"
+      - "443:443"
     volumes:
       - web-root:/usr/share/nginx/html
+      - ./certs:/etc/nginx/certs:ro
```

然后重建 nginx：

```bash
docker compose -f deploy/docker-compose.yml up -d --build nginx
docker compose -f deploy/docker-compose.yml logs --tail=30 nginx
```

### 5.5 验证

浏览器打开 `https://你的域名/`：
- 地址栏有小锁 → 证书 OK
- 能看到前端页面 → nginx 正常

```bash
curl https://你的域名/api/statistics/overview
```

返回 JSON 就说明 **小程序要走的这条路已经通了**。

## 6. 阶段五：小程序端（1 小时）

### 6.1 注册小程序（免费）

1. 打开 mp.weixin.qq.com → 立即注册 → 选「小程序」
2. 主体类型选**个人**，填身份证、手机号、邮箱
3. 微信扫码 + 人脸核身
4. **不需要交 300 元认证费**（那是企业主体才要的）

注册完在「设置 → 基本设置」里找到 **AppID**，记下来。

### 6.2 填 AppID

编辑 `miniapp/src/manifest.json`，把 `mp-weixin` 下面的 `appid` 填上：

```json
"mp-weixin": {
  "appid": "wx1234567890abcdef",
  ...
}
```

> 根级那个 `"appid": ""` 是 uni-app 的 DCloud 号，CLI 项目留空即可，不用管。

### 6.3 填线上接口地址

编辑 `miniapp/.env.production`，取消注释并换成你的域名：

```
VITE_API_BASE=https://你的域名/api
```

> 注意末尾的 `/api` 是**路径**不是端口，别删。nginx 靠它把 `/api/xxx` 转成后端的 `/xxx`，图片 `/api/upload/...` 也会一起转。
> 本地演示不受影响：这个文件不填，构建出来还是 `localhost:8081`（已实测两种状态都正常）。
> **改完必须重新 `npm run build:mp-weixin` 才生效**——地址是编译期写进代码的，不是运行时读的。
> 这个文件在 `.gitignore` 里（不会提交），换电脑后需要重新建一次。

### 6.4 构建

```bash
cd miniapp
npm run build:mp-weixin
```

产物在 `miniapp/dist/build/mp-weixin`。

### 6.5 配置服务器域名（关键一步）

小程序后台 → **开发管理 → 开发设置 → 服务器域名** → request 合法域名，填：

```
https://你的域名
```

规则：
- **只能填域名**，不能带路径、不能带端口、不能带 `/api`
- 必须是 https
- **域名必须已 ICP 备案**，没备案填进去会提示失败——这是硬门槛
- 每月只能改 5 次，想好再填

> 你的小程序端没有文件上传功能（头像走的是后端 `/upload` 静态映射，`<image>` 加载 https 图片不需要配 downloadFile 域名），所以**只配 request 一项就够了**。

### 6.6 上传体验版

1. 打开微信开发者工具 → 导入项目 → 目录选 `miniapp/dist/build/mp-weixin` → 填 AppID
2. 右上角「上传」→ 版本号填 `1.0.0`，备注随便写
3. 小程序后台 → **管理 → 版本管理** → 找到「开发版本」→ 点「选为体验版」
4. 后台 → **管理 → 成员管理 → 体验成员** → 添加朋友的微信号（**最多 15 人**）
5. 把体验版二维码发给朋友，扫码即用

> 体验成员必须**先关注你的小程序或已被添加为体验成员**才能扫码进入，否则会提示"无权限"。

### 6.7 隐私保护指引（建议填）

后台 → 设置 → 服务内容声明 → 用户隐私保护指引。按实际情况勾选：

- 用户主动填写的日记内容、情绪记录
- 用户账号信息（昵称、头像）
- 如果注册流程收集了手机号，也要勾上

不填也能跑，但体验成员第一次进入可能弹「隐私协议未配置」的提示，填了更干净。

## 7. 五个必踩的坑（提前知道能省一天）

**① `urlCheck: false` 带不到线上。**
`manifest.json` 里 `"urlCheck": false` 只对开发者工具模拟器生效。体验版在朋友手机上**照样校验域名**，所以域名没配好就是"网络请求失败"，没有例外。

**② 域名没备案，后台根本填不进去。**
微信会直接提示域名未备案。这就是为什么第 2 节必须先做——它是所有事情的前置。

**③ 后台配的域名和代码里的路径是两回事。**
后台填 `https://xxx.com`，代码里 `BASE_URL=https://xxx.com/api` 是允许的。路径不受限制，只限制域名和端口。

**④ 证书必须是受信任机构签发的。**
自己用 openssl 生成的自签证书，浏览器点"继续访问"能过，但**微信直接拒绝**。必须用云厂商免费 DV 或 Let's Encrypt。

**⑤ 2G 内存会被 MySQL 吃垮。**
三个容器（MySQL 8 + JVM + Nginx）在 2G 机器上很容易 OOM，表现为后端容器反复重启。先加 2G swap，或者直接买 4G。

## 9. 答辩话术怎么调

原来的定位是"不上线、纯演示"，现在改成"**已真实部署，微信里可扫码体验**"，其实是个加分项，但要说准：

> "小程序端已完成真实环境部署，通过 ICP 备案域名 + HTTPS 直连云端 SpringBoot 服务，采用体验版形式做小范围真实用户验证，覆盖核心记录链路。正式上架涉及服务类目与内容合规审核，不在本次毕设范围内。"

被问到"为什么不上架"：

> "日记类内容在微信侧归属社交-日记类目，个人主体未开放，需要企业主体资质；本项目的验证目标是核心链路的真实可用性，体验版已经能达到这个目的。"

这样既不显得做不了，也说明你知道边界在哪。
