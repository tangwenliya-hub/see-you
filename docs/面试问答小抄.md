## 一、ECharts 可视化（前端岗必问）

### ⭐ Q1：你的图表封装是怎么做的？为什么封装？
**结论先行**：项目里有 15 个图表实例，我封装了一个 `useChart` 组合式函数做统一管理。

解决三类问题：
1. **生命周期**：init/setOption/resize/dispose 分散在各页面手写容易漏 dispose 造成内存泄漏（个人中心 tab 用 v-if 切换时 DOM 被销毁，旧实例还挂在已移除节点上）。useChart 在 `onBeforeUnmount` 统一 dispose，且只对「未失效」实例操作。
2. **resize 监听重复**：N 个页面 N 个 window resize 监听 → 改为**全局单例监听 + requestAnimationFrame 合并**，注册表为空时自动解绑。
3. **大数据量渲染**：按数据量（阈值 2000 点）自动开启 progressive 渐进渲染、line 用 LTTB 采样、bar/scatter 开 large 模式，小图表保留动画。

加分句：「这是个纯函数设计——性能配置那部分抽成了 `withPerf(option)` 纯函数，方便单测。」

### ⭐ Q2：ECharts 6 你踩过什么坑？（真实 bug，非常加分）
**答**：升级 ECharts 6 后，后台数据看板报 `Cannot read properties of undefined (reading 'axisBuilder')`。
**定位过程**：控制台同时报 `Unknown series undefined` → 判断是 series 丢了 type → 检查代码发现二次更新时写了 `setOption(部分字段, { notMerge: true })`。
**根因**：`notMerge: true` 会**整体丢弃**第一次的完整配置，二次只传了数据没传 type，坐标轴组件拿不到依赖直接崩。ECharts 5 容忍这个写法，6.x 不再容忍。
**修复**：数据更新改用 merge 模式（省略第二个参数），首次初始化的 notMerge 保留。还在独立 HTML 里做了最小复现验证。

### Q3：桑基图/词云/回归散点分别怎么实现的？（挑两个最熟的讲）
- **回归散点**：后端 `/statistics/my/scatter` 只返回近 90 天的 (睡眠时长， 情绪指数) 样本；**回归线由前端用最小二乘计算**——斜率 b = Σ(x-x̄)(y-ȳ) / Σ(x-x̄)²，截距 a = ȳ - b·x̄，再算相关系数 r 判断相关性强度，用 markLine 画回归线。
- **词云**：后端对日记内容做**中文二元分词**（相邻两个汉字组成词，无词典轻量方案）+ 停用字过滤 + 频次阈值（≥5）+ Top40，前端 echarts-wordcloud 渲染。
- **桑基图**：左侧「活动」右侧「情绪」，value 为该活动当日出现且伴随该情绪的次数。

### Q4：暗色主题怎么跟随的？
图表颜色不写死，通过 CSS 变量取当前主题色（`getComputedStyle` 读取），主题切换时重新 setOption。

## 二、鉴权与安全（后端深度题）

### ⭐ Q5：JWT 为什么还要配一张会话表？
**结论先行**：JWT 是无状态的，签发后服务端无法作废——这正是它的优点也是缺点。

我的场景需要服务端控制权：
1. 用户在「账号设置」踢掉不认识的设备（强制下线）
2. 注销账号后所有会话立即失效
3. 记录登录设备/IP 供安全中心展示

**做法**：登录时生成 JWT 同时插入 `sys_user_session`（记录设备、IP、最后活跃时间）；拦截器校验 JWT 签名后**再查会话表**，会话不存在或 status=0 就 401。踢设备 = 改会话状态，立即生效。

### ⭐ Q6：越权（IDOR）怎么防的？
**原则**：**userId 一律从 token 解析，永远不信前端传参**。
- 查列表/详情：SQL 里强制 `WHERE user_id = #{token解析的uid}`（资源归属校验）
- 改/删：先查归属再操作，别人的资源返回 404/403
- 管理员代查是显式的：`isAdmin() && userId != null` 才允许按指定 userId 查
- 实测：带着别人的 ID 调接口，参数被忽略、返回自己的数据

### Q7：登录失败锁定怎么设计？
`sys_login_attempt` 表记录失败次数：**5 次失败锁 10 分钟**，锁定后计数清零、窗口过期自动解锁；每次失败都返回固定文案「账号或密码错误」（不泄露账号是否存在）。这块写了 15 个单元测试覆盖边界。

## 三、单元测试（质量意识题）

### ⭐ Q8：49 个测试都测了什么？测出过 bug 吗？
**覆盖 5 个最易错的纯逻辑单元**：
| 测试类 | 数量 | 内容 |
|---|---|---|
| StatisticsLogicTest | 17 | 情绪映射边界（null/越界）、连续打卡四种边界（空数据/今天已打卡/断在昨天/同天多篇）、中文二元分词 |
| AccountSecurityServiceTest | 15 | 失败锁定全流程、找回密码验证码过期/次数上限、心跳节流 |
| CsvUtilTest | 6 | CSV 转义、BOM、公式注入防护（`=`/`+`/`-`/`@` 开头前置单引号，防 Excel 公式注入） |
| JwtUtilTest | 5 | 签发/解析/篡改拒绝/过期拒绝 |
| PageLimitTest | 5 | 分页参数边界（0/负数/超大截断） |

**真的测出过 2 个 bug**：① 停用字表把「今天」「心情」误杀，导致词云缺核心词；② 日记 CSV 导出缺 BOM，Excel 打开乱码。这也验证了写测试的价值——不是形式，是能抓真问题的。

## 四、WebSocket 与其他

### Q9：WebSocket 用在哪？怎么保证连接稳定？
反馈消息实时推送给管理员。踩过一个真 bug：握手后 handler 里把 attrs 的 userId 强转 String，但存的是 Long → ClassCastException → 连接即断 → 前端无限重连。修复为 `String.valueOf` 转换，实测 12 秒零断连。握手阶段做了 JWT + 会话双重校验，未登录连不上。

### Q10：评论为什么要"先审后显"？
UGC 内容合规需要。`status` 三态：0 待审核 / 1 通过 / -1 拒绝；列表 SQL 只返回「已通过 + 本人自己的待审核与被拒评论」（被拒的作者可见并标红，避免用户以为评论丢了）。个人中心有「我的评论」标签页统一看审核状态。
