# 无感记录模块 · 答辩演示指南

> 解决一个问题：无感记录依赖 H5 端真实埋点（停留时长、点击数、活跃时段），
> 演示环境不可能在几分钟内自然攒出一个月的行为数据，所以模块打开是空的。
> 本文给出一键播种方案与**保证出结果**的演示动线。

---

## 一、一键准备（30 秒）

```bash
# 生成 60 天 × 8 场景 = 480 条行为特征，并打开 test 账号的无感开关
mysql -u root -p see_you < see_you/sql/migration/20261028_seed_sense_demo.sql
```

脚本做了三件事：
1. 打开 `test` 账号的三个 opt-in 开关：`sense_enabled` / `sense_behavior` / `sense_text`
2. 清空窗口内旧特征后重新生成（**幂等，可反复执行**）
3. 打印核对结果：应为 `480 行 / 60 天 / 8 个场景`

启动后端，用 `test` 账号登录。

---

## 二、演示动线（按这个顺序，一定能出结果）

### 1. 展示"采了什么、没采什么"（隐私卖点）

我的 → **无感** 标签页 → 查看开关与说明。

讲点：只采集**四类聚合数值**（停留毫秒数、进入次数、点击次数、24 小时活跃位图），
数据库里没有任何文本字段，管理员也查不到他人行为数据，全部默认关闭需用户授权。

### 2. 触发推测（核心演示）

**写日记** → 内容栏输入与当天状态一致的文字 → 点「帮我猜一下」。

系统会返回：推测情绪、置信度、**「你最像哪一天」的相似日解释**、Top3 候选。

> ⚠️ **关键**：输入的文字要和你"今天的情绪状态"一致。
> 三通路是行为 + 文本 + 时序，如果文字说"难过"而行为特征显示活跃亢奋，
> 两条证据互相抵消，置信度会掉到阈值以下，系统就会**拒绝推荐**。
> 这不是 bug，见下一节——它是个可以主动讲的亮点。

### 3. 确认 / 驳回

- 点「采纳」→ 生成一条 `source=2` 的推测日记，**可溯源到具体预测记录**
- 点「不对」→ 该条不进入下一轮训练样本（避免模型自我循环）

### 4. 情绪预警

我的 → 情绪预警 → 「重新评估」。

判定规则可解释：滑动窗口 7 天、窗口内低落 3 天二级 / 5 天三级、同级冷却不重复打扰，
每条预警都能回溯触发条件与低落天数，全程带非医疗免责声明。

> 注意：test 账号近期情绪不低落，预警**不会触发**，这是正确结果。
> 想演示预警，先连续几天记录消极情绪，或临时造数据。

## 三、为什么有时"不给建议"？——把它讲成设计亮点

融合置信度公式：`confidence = P(top1) × √(通路数 / 3)`

| 场景 | 通路数 | 结果 |
|---|---|---|
| 三通路同向 | 3 | 实测 **67%**，正常给出建议 |
| 仅行为 + 时序 | 2 | 约 43%，**低于 45% 阈值则拒绝** |
| 行为与文本互相矛盾 | 3 | 约 30%，拒绝并给出人话解释 |

**设计意图**：参与证据越少越要打折（孤证不立）；证据互相冲突时宁可留空也不误导。
阈值 `app.sense.min-confidence=0.45` 可配。

评委追问"那你怎么保证有用"时的答法：
> 系统对自己的不确定是**显式**的——宁可说"这次不猜了"也不给一个错误的情绪标签，
> 因为错误的情绪反馈比没有反馈伤害更大。

## 四、数据性质声明（重要，答辩必须主动说）

播种脚本生成的特征与真实日记情绪之间存在**构造性关联**（按"每类情绪对应一组行为指纹"合成）。

- ✅ **可以证明**：链路打通、算法实现正确、交互完整、保守阈值生效
- ❌ **不能证明**：KNN 的真实准确率（用标签造特征再预测标签属于循环论证）

实测参考（仅说明实现正确，不是准确率指标）：在合成数据上 KNN 投票集中度达 **91.6%**，
且与其当天真实日记情绪一致——这说明距离度量、加权投票、归一化实现无误。

真实准确率需待真实埋点采集后重跑 `ModelEvaluationTest` 得到，论文里应如实写明这一点。


未播种时自动跳过（不会误报失败）。
