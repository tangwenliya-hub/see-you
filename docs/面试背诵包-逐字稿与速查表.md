## 【标准版 · 约3分钟】

面试官您好，我叫（你的名字），目前在读软件工程专业，方向是全栈开发，平时主要用 Java + Spring Boot 做后端、Vue3 做前端，熟悉 MySQL 数据库和 Git 版本管理。（停顿）

我今天想介绍的项目叫「绪见」，是一个个人情绪记录与可视化平台。它要解决的问题很简单：市面上的情绪类工具要么只能写日记、要么只能做测评，数据是割裂的，用户看不到自己长期的情绪变化。所以我把「记录、统计分析、风险提醒」串成了一条完整链路，用户每天记录心情和日记，系统自动生成趋势图表，情绪持续偏低时给出分级提醒。（停顿）

技术栈上，后端用 Spring Boot 3 + MyBatis-Plus + MySQL 8，前端用 Vue3 + Pinia + ECharts 6，另外还用 uni-app 做了一个微信小程序端，三端共用同一套后端 REST 接口。（停顿）

下面我重点讲四条我比较熟悉的核心链路。

**第一条是账号登录鉴权。** 注册时密码用 BCrypt 加密后存进 `sys_user` 表，数据库里不存明文；登录走 `POST /user/login`，后端校验账号密码后签发 JWT 返回给前端，前端把 token 存在本地，之后每个请求在请求头带上 token，后端用 JWT 拦截器统一校验。另外我还加了一张会话表 `sys_user_session`，因为纯 JWT 是无状态的、签发后没法作废，结合会话表就能实现「踢下线」和多设备管理；同时登录连续失败 5 次会锁定 10 分钟，存在 `sys_login_attempt` 表里。（停顿）

**第二条是情绪日记的增删改查。** 这是最核心的业务表 `psy_diary`，记录用户每天选的情绪类型、情绪强度、睡眠时长、压力值、运动时长和日记正文。后端按 Controller、Service、Mapper 三层组织，用 MyBatis-Plus 做单表 CRUD 和分页；前端写日记表单提交到 `POST /diary/save`，列表页调 `GET /diary/list` 做分页展示，支持编辑 `PUT /diary/update`、删除 `DELETE /diary/{id}`，还做了导出功能。（停顿）

**第三条是数据统计与可视化。** 个人统计接口比如 `GET /statistics/my/trend` 拿情绪趋势、`GET /statistics/my/emotion` 拿情绪分布，前端拿到数据后用 ECharts 渲染折线图、柱状图和热力图。这里有一个设计细节：个人数据查询都强制按 `user_id + diary_date` 建了联合索引，而且 userId 一律从 token 里解析，不相信前端传的 id，防止越权看到别人的数据。（停顿）

**第四条是情绪风险预警。** 系统按最近一段时间的低落记录做滑动窗口统计，分成轻度关注、中度提醒、高度关注三级，预警结果存在 `psy_risk_alert` 表，用户可以查看最新预警 `GET /risk/latest`、标记已读。这里的推测算法是参考成熟方案做的集成，我主要负责规则链路、接口对接和前端展示，算法底层原理还在继续学习。（停顿）

开发过程中我用 AI 工具辅助生成部分样板代码来提效，但核心的表结构设计、登录鉴权、越权防护和接口联调是我自己逐块梳理、调试和修改的；比如我专门处理过「图表数据异步渲染时机」和「token 过期跳登录」这类问题。（停顿）

不足的地方是工程经验还不够，复杂性能优化和算法底层接触得比较浅，所以我希望在实习里跟着团队补全规范开发、真实业务和部署运维这些能力。我学习能力比较强，也愿意从基础的 CRUD 和 Bug 修复做起。谢谢面试官。

## 三、一条完整请求链路（被问「一次请求怎么走的」就背这条）

以「登录后新增一条日记」为例：

```
前端写日记点保存
  → axios POST /diary/save，请求头带 Authorization: Bearer token
  → 后端 JWT 拦截器先校验 token（无效直接 401 跳登录）
  → Controller（PsyDiaryController.save）接收 @RequestBody
  → Service 层业务处理：从 token 解析 userId 塞进对象、校验参数
  → Mapper（MyBatis-Plus）把数据 insert 进 psy_diary 表
  → 返回 Result{code:200, data:true}
  → 前端收到成功提示，刷新列表重新调 /diary/list
```

**一句话版**：前端发请求 → 拦截器验 token → Controller 接参 → Service 处理 → Mapper 操作 MySQL → 返回 JSON → 前端渲染。

## 五、术语人话解释（你说不懂的那些词，先背这句人话版）

| 术语 | 面试能说出口的人话解释 |
|---|---|
| **JWT** | 登录成功后端发的一串令牌（三段：头/载荷/签名），之后请求带着它证明身份，服务端不存 session、靠签名验真伪。 |
| **BCrypt** | 一种单向加密算法，密码加密成乱码存库，登录时比对哈希，不可逆、带随机盐，防明文泄露。 |
| **拦截器 Interceptor** | 每个请求进来先过一道关卡，统一做 token 校验、白名单放行（注册登录不用 token）。 |
| **MyBatis-Plus** | MyBatis 的增强工具，单表 CRUD 不用写 SQL，提供 `BaseMapper`、分页插件、条件构造器。 |
| **联合索引** | `(user_id, diary_date)` 两个字段一起建索引，按「先用户、再日期」查询很快；遵循最左前缀原则。 |
| **分页** | 前端传 page/pageSize，后端用 `LIMIT` + 分页插件返回当前页数据和总数，避免一次查全表。 |
| **RESTful** | 用 HTTP 方法表动作：GET 查、POST 增、PUT 改、DELETE 删，URL 指向资源（如 `/diary/123`）。 |
| **Pinia** | Vue3 官方状态仓库，跨页面共享数据，比如登录后的用户信息。 |
| **ECharts** | 图表库，`init(dom)` 初始化、`setOption()` 喂数据配置渲染折线/柱状/热力图。 |
| **越权 IDOR** | 别人改请求里的 id 想看你数据；防护办法：userId 只从 token 取，不信前端传参。 |
| **事务 `@Transactional`** | 一组操作要么全成功要么全回滚，防止中途出错留下脏数据。 |
| **Git 分支** | `main` 主分支，开发拉 `dev`/功能分支，提交 `add→commit→push`，最后合并。 |
