# 绪见 · 数据库说明

库名 `see_you`，字符集 `utf8mb4`。共 21 张业务表 + 1 张可清理的遗留表（`sys_log`，操作日志模块已下线）。

## 一、表清单

### 用户与账号安全

| 表 | 说明 | 关键字段 |
|---|---|---|
| `sys_user` | 用户 | `username`、`password`(BCrypt)、`role`(0用户/1管理员)、`status`(0禁用/1正常)、`email`、主题偏好字段 |
| `sys_user_session` | 登录会话（多设备管理） | `token`、`status`(1在线/0被踢)、`last_active_time`（"当前在线"= 30 分钟内有心跳） |
| `sys_login_attempt` | 登录失败计数 | `fail_count`（5 次锁 10 分钟）、`lock_until` |
| `sys_pwd_reset` | 找回密码凭证 | `token`、`code`(6 位 SecureRandom)、`expire_time`(10 分钟)、`used` |

### 日记与情绪

| 表 | 说明 | 关键字段 |
|---|---|---|
| `psy_diary` | 日记（核心表） | `user_id`、`diary_content`、`emotion`(1~9)、`intensity`、`sleep_hours`、`stress_level`、`exercise_min`、`diary_date` |
| 索引 | `idx_uid_date (user_id, diary_date)` | 个人统计（趋势/热力图/散点）都按 `user_id + diary_date` 过滤，此索引覆盖全部查询 |

> 情绪编号全站统一：**1 开心 / 2 平静 / 3 疲惫 / 4 难过 / 5 生气 / 6 焦虑 / 7 兴奋 / 8 满足 / 9 其他**。
> 情绪指数字典（1→100、2→70、3→50、4→20、5→25、6→40、7→90、8→85、9→55）在
> `StatisticsController.EMOTION_INDEX`、`StatisticsMapper` 的 SQL、前端 `utils/constants.js` 三处同步维护，改动必须三处一起改。

### 心理测评

| 表 | 说明 |
|---|---|
| `psy_test` | 量表（60 套，含英文缩写命名的标准量表） |
| `psy_test_question` | 题目（挂在量表下） |
| `psy_test_option` | 选项（含分值） |
| `psy_test_record` | 作答记录（`total_score`、`level`、`result_emotion`） |
| `psy_test_result_grade` | 结果分级（后台按量表配置：分数区间 → 等级名/描述/建议，用户端优先展示） |

### 媒体资源

| 表 | 说明 |
|---|---|
| `psy_audio` | 心理 FM 音频（`audio_url`、`cover_img`、`lyric` 支持 LRC） |
| `psy_video` | 绪见学堂视频（`video_url`、`cover_img`、`play_count`） |
| `psy_history` | 播放历史（`resource_type` 1=音频 2=视频，upsert 按 user+type+resource 去重） |

### 互动

| 表 | 说明 |
|---|---|
| `psy_comment` | 评论（`status` 0=待审核；`user_id` 由服务端从 token 强制写入） |
| `psy_like` / `psy_collect` | 点赞 / 收藏（`resource_type` + `resource_id` 定位资源） |

### AI 与反馈

| 表 | 说明 |
|---|---|
| `psy_ai_chat` | AI 对话（带 `session_id`，格式 `s_{uid}_{ts}_{rand}`，上下文按会话重建） |
| `psy_ai_words` | AI 关键词话术库（后台可维护，`keyword` → `reply_text`） |
| `psy_feedback` | 意见反馈（`deleted` 软删除位；用户删除后后台仍可见） |
| `psy_feedback_message` | 反馈往来消息（用户反馈 / 管理员回复 / 用户补充三种 `sender_type`） |

### 可清理

| 表 | 说明 |
|---|---|
| `sys_log` | 旧操作日志模块的表，代码已删除，可 `DROP TABLE sys_log;` |
| `psy_ai_chat_bak_20261010` | 一次数据库调整前的手工备份，确认无需回滚后可删 |

| 脚本 | 内容 | 用途 |

## 三、设计要点（论文可直接引用）

1. **个人统计全部走 `(user_id, diary_date)` 联合索引**，且聚合下推 MySQL（GROUP BY / AVG(CASE)），接口响应与数据量解耦——实测 2 万条日记下统计接口从 ~700ms 降到 2~25ms（见 `docs/论文素材包.md`）。
2. **按天取数的去重策略**：趋势/热力图用 `MAX(diary_id)` 子查询取"每天最后一条"，避免同一天多篇日记把明细全拉回内存。
3. **所有越权防护在服务端**：个人数据接口的 `userId` 一律从 JWT 取，前端传参仅作展示参考（管理员可显式代查）。
