# 静态资源说明

`frontend/public/` 下的目录分两类，入库策略不同：

## 一、UI 素材（入库，已压缩）

| 目录 | 内容 | 状态 |
|---|---|---|
| `img/` | 页面装饰图、表情、演示截图（被 `src/` 直接引用 82 个文件） | 已批量压缩：122.6MB → 27.7MB（长边 1920px、PNG 调色板量化 80 / JPG 质量 82） |
| `avatar/` | 默认头像 | 已压缩 |
| `bg/` | 背景图 | 已压缩 |
| `vite.svg` | favicon | 保留 |

这些文件被前端代码以 `/img/xxx.png` 字面量引用，**必须随仓库分发**，否则拉代码后界面大量缺图。

## 二、运行期内容数据（不入库）

| 目录 | 内容 | 说明 |
|---|---|---|
| `video/` | 心理视频（91MB） | 数据库 `psy_video.video_url` 记录路径，属内容数据 |
| `audio/` | 治愈 FM 音频（76MB） | 数据库 `psy_audio.audio_url` |
| `diary/` | 日记图片（15MB） | 用户上传 |
| `cover/` | 资源封面 | 用户上传 |
| `user/` | 用户上传 | 用户上传 |

它们**不被代码引用**（源码里的 `/video/list`、`/diary/whisper` 等是后端 API 路径，不是静态资源），已加入 `frontend/.gitignore`。

## 三、部署时的处理方式

1. **从旧环境迁移**：直接拷贝 `public/{video,audio,diary,cover,user}` 到新机器同路径即可，nginx 与 Vite dev server 都按静态目录伺服。
2. **全新环境**：执行后端管理员上传功能重新灌入演示资源，或从资源种子包解压（如另行提供）。
3. **构建**：`npm run build` 会把 `public/` 全量拷入 `dist/`，这是预期行为；若部署到服务器，建议视频/音频走 nginx 独立目录或对象存储，减小前端发布包体积。

## 四、再次压缩

如后续新增大图，可用 `Temp/imgtool/compress.mjs`（依赖 sharp）重跑，脚本只会处理超过 800KB 的文件。
