# 绪见 · 换机交接指南

> 目标读者：换了新电脑的你，以及新电脑上的 AI 助手。
> 目标：10 分钟读完，30 分钟把项目跑起来，并且不踩老机器上踩过的坑。

---

## 0. 一句话认识项目

个人情绪追踪平台（毕设）：Spring Boot 3 + Vue 3 + 微信小程序三端，核心闭环是
**无感情绪记录（KNN+AR(1) 推测）→ 风险三级预警 → AI 陪伴疏导**。
规模：27 张业务表（另含 1 张遗留备份表） · 25 个 Controller · 250 个 HTTP 接口 · 100 个测试。

- 仓库：`https://gitee.com/TangZaiLiii/a-glimpse-ahead`（master）
- 更完整的项目介绍见根目录 `README.md`，本文只讲**换机**相关的事。

## 1. 哪些东西不随 git 走（换机前必须知道）

| 东西 | 在老机器哪 | 到新机器怎么办 |
|---|---|---|
| **真实密钥配置** `application-local.yml` | `see_you/src/main/resources/` | **不在仓库里**。复制 `application-local.yml.example` 改名后逐项填真实值（见第 4 节） |
| **MySQL 数据库本身** | 本机 MySQL 服务 | 想保留老数据就在老机器 `mysqldump see_you > dump.sql` 带走；不需要历史数据就按第 3 节全新初始化 |
| **AI 会话/记忆** `.workbuddy/` | 工作区根目录 | 被 gitignore，不会跟过去。新机器上的 AI 靠本文档 + `docs/` 目录恢复上下文 |
| **依赖包** `node_modules` | 前端/小程序目录 | 不要拷贝，`npm install` 重装（跨机器拷贝 node_modules 容易坏） |
| **上传的图片** `upload/` | 后端运行目录 | 如有测试期上传的图片想保留，手动拷贝到新机器对应位置 |

**随 git 走的**：全部源码、SQL 脚本、`scripts/` 工具脚本、docs 文档、图片素材。

## 3. 首次启动（按顺序）

```bash
# ① 克隆
git clone https://gitee.com/TangZaiLiii/a-glimpse-ahead.git
cd a-glimpse-ahead

# ② 建库（字符集必须 utf8mb4）
mysql -u root -p -e "CREATE DATABASE see_you DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# ③ 执行 SQL：先跑 see_you/sql/base_schema.sql（基础表结构，必须最先），
#    再按文件名日期从旧到新跑 see_you/sql/migration/ 下全部脚本，
#    最后跑 see_you/sql/ 根目录 3 个初始化数据脚本（add_60_scales_full / add_ai_keywords / add_test_papers）

# ④ 后端（JDK 17，端口 8081）
cd see_you
cp src/main/resources/application-local.yml.example src/main/resources/application-local.yml
#    → 编辑它，填真实值（下一节），然后：
mvn package -DskipTests
java -jar target/see_you-0.0.1-SNAPSHOT.jar

# ⑤ 前端（端口 5173，已代理 /api 和 /ws 到 8081）
cd ../frontend
npm install
npm run dev
```

浏览器开 `http://localhost:5173`。默认账号：管理员 `admin / ******`，普通用户 `test / ******`。

小程序端（可选）：`cd miniapp && npm install && npm run dev:mp-weixin`，用微信开发者工具导入 `miniapp/dist/dev/mp-weixin`。

**跑起来后第一件事**：`node scripts/smoke.mjs` 跑冒烟测试，核心链路（登录/鉴权/无感推测/预警）全绿说明环境没问题。

## 4. `application-local.yml` 逐项说明（最容易翻车的一步）

| 字段 | 填什么 | 不填会怎样 |
|---|---|---|
| `spring.datasource.password` | 新机器的 MySQL root 密码，**必须加引号** | 纯数字密码不加引号会被 YAML 当八进制解析，报错很诡异 |
| `jwt.secret` | 随手改乱的随机串，**≥ 32 字符** | 长度不足后端直接启动失败（会提示你） |
| `spring.mail.*` | QQ 邮箱 + SMTP 授权码 | **可以留空**——自动降级为「接口回显验证码」，找回密码功能照常能测 |
| `ai.api-key` | DeepSeek 的 key | **可以留空**——AI 对话降级本地关键词库 |
| `upload.front-path` | 新机器 `frontend/public` 的**绝对路径** | 不改则上传的图片前端访问不到 |

## 5. 换机必改的硬编码（老机器路径残留）

`scripts/` 下的 E2E 验证脚本里硬编码了老机器的 mysql 客户端路径：

```
const MYSQL = 'E:/mysql-8.4.8-winx64/bin/mysql'
```

涉及文件：`seed_demo.mjs`、`verify_ai_harm.mjs`、`verify_ai_judge.mjs`、`verify_sse.mjs`、`verify_words.mjs`。
新机器上把它们改成自己的 `mysql.exe` 路径（或者给 mysql 加了 PATH 后简化写法）。
`smoke.mjs` 不依赖 mysql 客户端，不受影响。

## 6. 常用命令速查

| 命令 | 用途 |
|---|---|
| `node scripts/smoke.mjs` | 重启后端后跑冒烟测试（需 `--app.dev-captcha-log=true` 启动参数或 local.yml 里的对应开关） |
| `node scripts/seed_demo.mjs` | 造两个演示用户（点亮一级/二级预警），答辩演示前跑 |
| `node scripts/verify_*.mjs` | 预警 AI 精判 / SSE 推送 / 词库管理的端到端验证（测试数据自动清理） |
| `node scripts/analyze_frames.js` | 换头像框图后量圆环几何、给建议 scale |
| `mvn test -DDB_PASSWORD=你的密码 -DDB_USERNAME=root` | 100 个后端测试（含跨前后端情绪字典一致性测试） |
| `mvn test -Dtest=ModelEvaluationTest -DDB_PASSWORD=你的密码` | 重新生成 `docs/模型评估报告.md` |

## 7. 项目铁律（改代码前必读，都是踩过的坑）

1. **情绪字典单一真源**：九类情绪映射在前端 4 处、后端 2 处。改任何一处必须同步其余；一致性测试会拦截漏改。
2. **主题色板三处同步**：`App.vue ALL_THEMES`、`Profile.vue themeColors`、`AdminLayout.vue themeColors`，同名同 hex 同 main/bg1/bg2。用户端/后台主题存储键是分开的（`profile_theme` / `admin_theme`），别合并回去。
3. **统计接口的 Controller 不接 userId 入参**，一律从 token 取。否则会被 `/statistics/**` 白名单意外放开，越权。
4. **无感记录的 SQL 必带 user_id**，行为 DTO 不含文本字段——管理员也查不到他人行为数据，这是隐私红线。
5. **免责声明三处保留**：前端弹窗/卡片、`RiskProperties.disclaimer`、论文正文。
6. **ECharts 数据更新用 merge 模式**（`chart.set({...})` 不带 notMerge）；整配置重建时小心 ECharts 6 的 axisBuilder 报错。
7. **覆盖式更新**：直接改原文件，不新建 `xxx-old` / `backup` / `temp` 文件；旧代码留注释里。
8. **vite 代理目标写 `127.0.0.1` 别写 `localhost`**：Windows 上 localhost 可能解析成 ::1，而 http-proxy 不做 IPv4 回退，表现为重启后端后全部接口 502。
