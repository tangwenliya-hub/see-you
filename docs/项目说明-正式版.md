# 绪见 · 个人情绪追踪与陪伴平台 项目说明

## 一、项目背景

情绪健康是个人日常管理中最容易被忽视的部分。传统心理服务依赖线下咨询，存在成本高、门槛高、周期长的问题；市面上的情绪类应用多为单向记录工具，只提供日记与统计图表，缺乏对情绪状态变化的主动识别与干预能力，且行为数据普遍以明文收集，隐私风险突出。

针对上述问题，本项目构建一套个人情绪追踪与陪伴平台，实现三项核心目标：一是将情绪记录、量化分析、可视化呈现形成闭环，帮助用户建立自我觉察；二是在用户授权前提下，通过行为特征推测情绪状态，降低手动记录门槛；三是对持续低落的情绪状态进行分级识别，并发出关怀提醒。

考虑到用户使用场景的差异，平台采用一套后端服务同时支撑 Web、移动端 H5 与微信小程序三端。其中 Web 端面向深度使用，移动端 H5 面向随时记录，小程序端面向微信内的轻量记录入口，同一账号在三端数据完全互通。

> 边界声明：本平台的情绪推测与风险提醒属于健康辅助功能，不构成任何医疗诊断意见，系统在前端弹窗、接口返回与配置项中均强制附带非医疗免责声明。

## 二、系统功能

### 2.1 账号与安全体系

- 账号注册、登录、登出，支持用户名 / 密码与第三方账号登录
- 图形验证码防刷，验证码仅在开发模式下通过日志额外输出
- 连续登录失败锁定机制：5 次失败锁定 10 分钟，记录来源 IP 与尝试明细
- 找回密码：邮箱验证码核验后重置，邮件服务未配置时降级为验证码写入后端日志
- 会话管理：在线会话列表查询、单会话强制下线、批量下线其他设备
- 第三方账号两步绑定：首次登录未绑定账号时返回临时票据，由用户选择绑定已有账号或创建新账号
- 密码 BCrypt 加盐存储，JWT 签发与校验
- 管理员用户管理：用户列表、启用禁用、角色分配、Excel 批量导入

### 2.2 情绪日记

- 日记撰写、编辑、删除、分页查询、详情查看
- 九类情绪标签与情绪强度记录，按日期、情绪、关键词检索
- 日记归属二分类：手动记录与系统推测，推测来源可溯源到具体预测记录
- CSV 与 Excel 批量导出

### 2.3 无感记录

- 逐项隐私开关：全部采集项默认关闭，需用户显式授权后生效（opt-in）
- 七维日粒度行为特征采集，行为数据均按用户隔离存储
- 情绪推测：加权 KNN 与一阶自回归融合推测当日情绪，输出情绪类别与概率分布
- 推测结果确认与驳回，驳回数据不参与后续训练
- 行为特征与情绪相关性分析
- 行为数据导出与隐私操作审计日志

### 2.4 情绪风险预警

- 三级风险判定：轻度关注、中度提醒、高度关注
- 预警列表查询、概览统计、标记已读、确认处理
- 手动触发重新评估
- 同等级冷却机制，避免重复提醒
- 全程附带非医疗免责声明

### 2.5 心理测评

- 内置 60 套标准化量表，覆盖 PHQ-9 抑郁筛查、SDS 抑郁自评、BDI-II 贝克抑郁、GAD-7 广泛性焦虑、SAS 焦虑自评、STAI 状态-特质焦虑等抑郁与焦虑筛查工具
- 试卷与题目管理、量表检索
- 断点续答，中途退出可恢复作答进度
- 答题结果自动评分、分级判定与成绩查询

### 2.6 AI 情绪陪伴

- 多会话管理：创建、列表、切换、重命名、删除
- 上下文隔离：按会话独立重建最近 10 轮对话
- 单条回答重新生成
- 推荐量表名与测评模块联动，可直达对应量表
- 大模型调用失败时降级为本地关键词应答

### 2.7 资源中心

- 心理视频、治愈 FM、心理课程三类资源
- 资源浏览与播放，播放量统计
- 点赞、收藏、评论及其取消操作
- 评论审核与敏感词过滤
- 浏览历史记录

### 2.8 数据看板

- 全站统计：情绪分布、情绪趋势、资源分布、测评结果、综合概览、视频排行、活跃用户
- 个人统计：个人概览、情绪趋势、日历热力图、情绪分布、测评趋势、月度汇总
- 可视化形式涵盖柱状图、折线图、饼图、热力图、桑基图、散点图与关键词词云

### 2.9 反馈与消息

- 用户提交意见反馈工单
- 管理员回复与状态流转
- WebSocket 实时推送后台回复

### 2.10 后台管理

- 15 个管理页面，覆盖用户管理、内容管理、测评管理、预警管理、情绪词典管理、系统日志等

### 2.11 移动端与小程序

- 移动端 H5：断点式响应式适配，列表、表单、图表与弹窗在窄屏下的重排版与防溢出处理，底部标签导航
- 微信小程序：登录、主页、日记列表、写日记、AI 陪伴、个人中心，共用同一套 REST 接口

## 三、技术原理

### 3.1 技术架构

后端采用 Spring Boot 3.3.5（JDK 17）+ MyBatis-Plus 3.5.5 + MySQL 8 构建，共 25 个 Controller、210 个 HTTP 接口、21 张业务表。前端采用 Vue 3.5 + Vite 6 + Pinia + Vue Router + Element Plus 2.14 + ECharts 6；小程序端采用 uni-app + Vue 3。

系统分为四层：

- **客户端层**：Web、移动端 H5、微信小程序三端共用同一套 REST 接口与 JWT 鉴权协议，接口层通过请求适配器切换底层实现，业务调用代码保持不变。
- **接入层**：由拦截器统一处理跨域、鉴权与限流。JWT 拦截器按白名单放行公开接口，其余请求校验 token 并解析用户身份注入上下文。
- **业务层**：Controller 按业务域分组路由，Service 处理业务编排，复杂计算委托给算法层。
- **数据层**：MyBatis-Plus 完成对象关系映射与分页，自定义 XML 覆盖关联查询与批量操作。

关键中间件：MySQL 8 持久化；MyBatis-Plus 分页插件；BCrypt 密码散列；JJWT 0.12.6 令牌签发；WebSocket 实时消息；DeepSeek 大模型 API 作为 AI 对话的远程推理服务。

### 3.2 工作流程原理

**（一）请求处理流程**

客户端请求携带 Bearer Token 发起调用，拦截器先判断是否命中白名单：全站统计等公开接口直接放行；其余接口校验 token 签名与有效期，解析出 userId 注入请求上下文。Controller 接收参数后调用 Service，Service 通过 MyBatis-Plus 访问数据库并返回统一响应体（code / data / msg）。

身份归属一律以 token 解析结果为准，用户端接口不接受 userId 入参；确需支持查询他人的接口在 Service 层校验管理员身份，非管理员强制覆盖为本人 ID。

**（二）无感记录情绪推测流程**

系统在用户授权后按日粒度聚合行为，形成七维归一化特征向量并写入行为特征表。推测时执行双通路计算：

- **KNN 通路**：取该用户全部手动记录的日记（source=1）作为训练样本，计算当日特征向量与历史各日向量的加权欧氏距离，取距离最近的 K=5 个邻居，按距离倒数加权投票，得到基于"相似历史日"的情绪分布。训练样本只取用户手动记录、排除系统推测结果，避免模型自我循环导致误差逐轮放大。
- **AR(1) 通路**：取最近若干天的情绪序列，拟合一阶自回归模型，得到基于"近期趋势惯性"的预测分布。

两通路按加权系数融合，输出推测情绪类别及概率分布。置信度低于阈值（0.45）时不向用户推送，宁可留空也不误导。用户可以确认或驳回推测结果，确认为手动记录的日记进入下一轮训练样本。

**（三）情绪风险预警流程**

规则引擎以 7 天为滑动窗口读取用户近期的情绪记录与情绪指数，以窗口内低落天数、窗口均值、趋势斜率为判定输入，结合可配置阈值输出三级风险等级：

- 一级（轻度关注）：低落天数或均值达到初始阈值
- 二级（中度提醒）：低落天数达到更高阈值
- 三级（高度关注）：低落天数达到最高阈值

同一等级设置冷却期，冷却期内不重复生成同类预警，避免对用户造成打扰。全部判定为确定性规则，每个预警均可回溯具体触发条件并向用户展示判定依据。

识别口径采用宽口径（疲惫、难过、生气、焦虑），展示口径采用窄口径（难过、生气）。前者保证识别敏感性——持续疲惫与焦虑本身即为风险信号；后者保证统计结果符合用户直觉，避免将日常疲劳计为消极情绪。两者为展示层与计算层的职责分离，且满足识别口径包含展示口径的约束。

**（四）AI 对话上下文流程**

每次对话归属一个会话（session_id 携带用户 ID 与时间戳结构）。服务端接收用户消息后，按 sessionId 从数据库读取该会话最近 10 轮记录，组装为上下文消息数组，连同系统提示词一并提交大模型接口，生成结果写入消息表。用户发起新会话时生成新 sessionId，上下文自然隔离。若大模型调用失败或超时，降级为本地关键词匹配应答，保证功能可用性。

**（五）移动端适配原理**

移动端不另建独立工程，而是在既有 PC 样式之上追加断点样式层。样式层按 1024px / 768px / 375px / 360px 四档断点，逐项解除 PC 布局中的固定宽度、写死的左侧留白与最小宽度限制，并针对 iOS 输入框聚焦缩放、表格横向滚动、弹窗宽度作出约束。图表不采用整体缩放，而是通过 `setResponsive()` 注册 option 工厂函数，在跨越断点时依据当前宽度重新生成完整 option（图例位置、坐标轴标签旋转、边距等），从而在 30 余个图表零改动的前提下完成适配，且桌面端无回归。底部导航用于替代依赖鼠标悬停的顶部菜单，解决触屏无 hover 事件导致的导航不可达问题。

**（六）安全机制**

- 认证：JWT 无状态令牌 + BCrypt 密码散列
- 防爆破：图形验证码 + 连续失败锁定 + 会话强制下线
- 越权防护：用户归属身份一律从 token 获取，接口不接收 userId 入参
- 隐私隔离：无感记录的 SQL 查询一律携带 user_id 条件，行为数据传输对象不含任何文本字段，管理员亦无法查询他人行为数据
- 密钥管理：数据库口令、JWT 密钥、AI 密钥全部由环境变量注入，配置文件仅保留占位符，含真实凭据的本地文件纳入版本忽略
- 合规：情绪预警功能在三处位置强制保留非医疗免责声明
