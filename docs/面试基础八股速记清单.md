## 一、Java 基础（JD 第一条硬要求）

### 1. 面向对象 ⭐
- **三大特性**：封装（隐藏内部细节、暴露方法）、继承（子类复用父类代码并扩展）、多态（同一方法不同对象表现不同，靠重写+向上转型实现）。
- **重写 vs 重载**：重写(Override)是子类改父类方法实现（方法名参数相同）；重载(Overload)是同类中方法名相同、参数列表不同。
- **类与对象**：类是模板，对象是按类 new 出来的实例；`this` 指当前对象，`super` 指父类。
- **访问修饰符范围**（由大到小）：`public` > `protected` > 默认(包私有) > `private`。
- **接口 vs 抽象类**：接口定义规范（多实现、方法默认 public abstract）；抽象类有共同代码（单继承、可有普通方法和成员变量）。

### 2. 集合框架 ⭐
- **List（有序可重复）**
  - `ArrayList`：底层数组，**查询快、增删慢、线程不安全**，最常用。
  - `LinkedList`：底层链表，增删快、查询慢。
- **Set（无序不重复）**：`HashSet` 底层是 HashMap，靠 hashCode+equals 去重。
- **Map（键值对，键唯一）**
  - `HashMap`：键值对、无序、线程不安全；JDK8 底层数组+链表+红黑树（链表长度>8 转红黑树）。
  - `LinkedHashMap`：保插入顺序；`TreeMap`：按 key 排序。
- **Collection vs Collections**：前者是集合顶层接口；后者是集合工具类（`Collections.sort()`、`sort`、`shuffle`）。
- **遍历方式**：普通 for / 增强 for(`for(x:list)`) / Iterator 迭代器 / forEach。

### 3. 常用 API 与字符串 ⭐
- **String vs StringBuilder vs StringBuffer**：
  - `String` 不可变，拼接产生新对象；
  - `StringBuilder` 可变、**线程不安全、速度快**（单线程拼接用它）；
  - `StringBuffer` 可变、方法加 synchronized、线程安全但慢。
- **== vs equals()**：`==` 比基本类型比值、比引用类型比地址；`equals()` 默认比地址，String 等类重写后比内容。
- **== 比较两个 new String("a") 结果是 false**（地址不同），`equals` 才是 true。
- **包装类型**：int→Integer、自动装箱/拆箱；Integer 缓存 -128~127（了解即可）。

### 4. 异常体系 ⭐
- 顶层 `Throwable`，下分 `Error`（系统级错误，如 OOM，不处理）和 `Exception`。
- `Exception` 分：**受检异常（编译期必须处理，如 IOException）** 和 **运行时异常 RuntimeException（如 NullPointerException、IndexOutOfBounds、IllegalArgument）**。
- 处理：`try-catch-finally`；`finally` 无论是否异常都执行（常关流）；`throw` 方法内抛异常，`throws` 方法签名声明。
- 自定义异常：继承 RuntimeException。

### 5. 多线程（实习只考概念，不考锁细节）⭐
- **进程 vs 线程**：进程是资源分配单位（程序运行实例）；线程是 CPU 调度最小单位，一个进程含多个线程，共享内存。
- **创建线程两种常用方式**：继承 `Thread`、实现 `Runnable`（推荐，避免单继承局限）；另有 `Callable` 带返回值。
- **线程生命周期**：新建 → 就绪 → 运行 → 阻塞 → 终止。
- **`synchronized`**：加锁保证同一时刻只有一个线程执行同步块，保证原子性和可见性。
- **`start()` vs `run()`**：`start()` 才启动新线程；直接调 `run()` 只是普通方法调用、不开线程。
- **常见方法**：`sleep()` 休眠不释放锁；`wait()` 释放锁（配合 synchronized）；`join()` 等待线程结束。

### 6. IO 流（概念题）
- **字节流 vs 字符流**：字节流 `InputStream/OutputStream` 处理任意文件（图片、视频、二进制）；字符流 `Reader/Writer` 处理文本（自动编码）。
- **节点流 vs 处理流**：直接接文件是节点流；包一层缓冲的 `BufferedReader`/`BufferedInputStream` 是处理流，提升效率。
- 标准关闭顺序：先开后关、`finally` 里 close（新版 try-with-resources 自动关）。
- **BIO/NIO**（了解）：BIO 同步阻塞、一连接一线程；NIO 非阻塞、面向缓冲区、多路复用。

### 7. 其他高频小题
- **final**：修饰类不能继承、方法不能重写、变量不可重新赋值（常量）。
- **static**：属于类不属于对象，可直接 `类名.方法`；静态代码块类加载时执行一次。
- **泛型**：编译期类型检查，避免强制类型转换、消除类型错误；如 `List<String>`。
- **ArrayList 扩容**：默认初始容量10，扩容约1.5倍（了解）。
- **重载和重写区别**见1。
- **抽象类能不能 new？** 不能，只能被继承后实例化子类。

## 二、Spring Boot 后端（项目核心，高频）⭐

### 1. 核心概念 ⭐
- **IOC（控制反转）**：对象不再自己 new，而是由 Spring 容器创建和管理；**DI（依赖注入）**：容器把依赖对象注入进来。解耦、方便替换实现。
- **AOP（面向切面）**：把日志、事务、权限等公共逻辑抽成切面，在不修改业务代码的情况下切入；术语：切面Aspect、切点Pointcut、通知Advice、连接点JoinPoint。
- **Spring Boot 优势**：自动配置（`@EnableAutoConfiguration`）、起步依赖（starter）、内嵌 Tomcat、无需传统 XML、开箱即用。
- **启动类 `@SpringBootApplication`** = `@Configuration` + `@EnableAutoConfiguration` + `@ComponentScan`（扫描同包及子包组件）。

### 2. 常用注解 ⭐
| 注解 | 作用 |
|---|---|
| `@RestController` | = `@Controller` + `@ResponseBody`，方法返回 JSON |
| `@Controller` | 返回视图/页面 |
| `@RequestMapping("/diary")` | 类级/方法级路由前缀 |
| `@GetMapping` / `@PostMapping` / `@PutMapping` / `@DeleteMapping` | 对应 GET/POST/PUT/DELETE |
| `@RequestParam` | 接收 URL 查询参数 `?page=1` |
| `@PathVariable` | 接收路径参数 `/diary/123` |
| `@RequestBody` | 接收 JSON 请求体，绑定到对象 |
| `@Service` | 标记业务层 Bean |
| `@Mapper` / `@Repository` | 标记数据层 |
| `@Autowired` | 按类型注入；`@Resource` 按名称注入 |
| `@Component` | 通用组件注册到容器 |
| `@Transactional` | 声明式事务，出错自动回滚 |
| `@Configuration` + `@Bean` | Java 配置方式注册 Bean |

### 3. 请求与响应 ⭐
- **三层结构**：Controller（接参/路由/返回）→ Service（业务逻辑/事务）→ Mapper（数据库）。职责不混写。
- **统一返回 Result**：`{ code, message, data }`，code=200成功、401未登录、403无权限、500服务器错误。
- **HTTP 状态码**：200成功；301/302重定向；400参数错；401未认证；403禁止；404不存在；500服务端错误。
- **GET vs POST**：GET 用于查询、参数拼在URL、长度有限、可缓存；POST 用于新增/提交、参数在请求体、相对安全。
- **REST 风格**：GET查/POST增/PUT改/DELETE删，URL 用名词（`/diary`、`/diary/1`）。

### 4. JWT 与拦截器（项目重点）⭐
- **JWT 结构三段**：Header（算法声明）.Payload（用户信息/过期时间）.Signature（签名，防篡改）。
- **登录流程**：校验账号密码 → 生成 JWT 返回 → 前端存 localStorage → 后续请求头 `Authorization: Bearer token` → 后端拦截器解析验签。
- **JWT 优点**：无状态、服务端不存会话、易扩展；**缺点**：签发后难主动失效、不适合存大量数据（所以项目加了会话表控制踢下线）。
- **拦截器 HandlerInterceptor**：重写 `preHandle()` 在业务前执行，做 token 校验；白名单（登录/注册/验证码）放行，其余无 token 返回 401。
- **Spring MVC 执行流程**（了解）：请求 → DispatcherServlet → HandlerMapping 找控制器 → 拦截器链 → Controller → 视图/JSON 写出。

### 5. 事务 @Transactional ⭐
- 作用在方法/类上；**默认只对 RuntimeException（运行时异常）回滚**，受检异常默认不回滚（可配 `rollbackFor`）。
- **传播行为常用 REQUIRED**：有事务就加入、没有就新建。
- 失效场景（了解）：同类内部方法自调用、方法非 public、异常被 try-catch 吞掉、数据库引擎非 InnoDB。
- **ACID 见 MySQL 部分**。

### 6. 其他高频小题
- **依赖注入两种方式**：字段注入 `@Autowired`；构造器注入（推荐，便于测试、不可变）。
- **Spring Bean 作用域**：默认 `singleton` 单例；`prototype` 每次新建。
- **SpringBoot 启动内置 Tomcat**，打成 jar 直接 `java -jar` 运行，无需单独部署 war。
- **文件上传**：`MultipartFile` 接收；限制大小在 `application.yml` 配置。
- **跨域 CORS**：前端 5173、后端 8081 不同端口会跨域；后端用 `@CrossOrigin` 或全局配置允许跨域，前端 Vite 代理 `/api` 转发。

## 三、MySQL 数据库（必出题）⭐

### 1. 必背 SQL（能手写）⭐
```sql
-- 新增
INSERT INTO sys_user (username, password, role, create_time) VALUES (?, ?, ?, NOW());
-- 条件查询（带分页）
SELECT id, emotion, diary_content, diary_date
FROM psy_diary
WHERE user_id = ?
ORDER BY diary_date DESC
LIMIT 10 OFFSET 0;          -- OFFSET = (page-1)*pageSize
-- 更新
UPDATE psy_diary SET emotion = ?, intensity = ? WHERE id = ? AND user_id = ?;
-- 删除（项目多用软删除：UPDATE 置 deleted=1）
DELETE FROM psy_diary WHERE id = ?;
-- 分组聚合（统计每日情绪）
SELECT diary_date, AVG(intensity) AS avg_i, COUNT(*) AS cnt
FROM psy_diary WHERE user_id = ?
GROUP BY diary_date ORDER BY diary_date DESC;
-- 联表（内连接取用户信息）
SELECT d.*, u.username FROM psy_diary d
INNER JOIN sys_user u ON d.user_id = u.id;
```
- **左连接 LEFT JOIN**：左表全保留，右表无匹配补 NULL；内连接 INNER JOIN：只保留两边匹配的行。
- **WHERE vs HAVING**：WHERE 在分组前过滤行、不能用聚合函数；HAVING 在 GROUP BY 后过滤分组结果、可用聚合。

### 2. 索引 ⭐
- **作用**：相当于书的目录，加速 WHERE/ORDER BY/GROUP BY 查询，降低全表扫描。
- **分类**：主键索引 PRIMARY（唯一非空）、唯一索引 UNIQUE、普通索引 INDEX、联合索引（多列组合）。
- **联合索引最左前缀原则**：`(user_id, diary_date)` 查询必须先用到 user_id 才能发挥索引。
- **优缺点**：加快读；但拖慢 INSERT/UPDATE/DELETE、占用磁盘空间，不是越多越好。
- **索引失效常见情况**：对索引列用函数/运算、`LIKE '%xxx'` 前导通配、类型隐式转换、不满足最左前缀、OR 两侧有未索引列。
- **EXPLAIN**：查看执行计划，type 列看是否走索引（const/ref 好，ALL 全表扫描差）。

### 3. 事务 ACID ⭐
| 特性 | 含义 |
|---|---|
| 原子性 Atomicity | 事务内操作要么全成功、要么全回滚（undo log） |
| 一致性 Consistency | 事务前后数据整体保持一致、合法约束不被破坏 |
| 隔离性 Isolation | 并发事务之间互不干扰 |
| 持久性 Durability | 提交后永久保存（redo log 落盘） |

- **隔离级别（由低到高）**：读未提交 Read Uncommitted → 读已提交 Read Committed → **可重复读 Repeatable Read（MySQL InnoDB 默认）** → 串行化 Serializable。
- **对应问题**：脏读（读到未提交数据）、不可重复读（同事务两次读同值不同，侧重被 update）、幻读（两次查询行数不同，侧重 insert）。
- **InnoDB vs MyISAM**：InnoDB 支持事务、行锁、外键；MyISAM 不支持事务、查询快（项目用 InnoDB）。

### 4. 表设计与范式 ⭐
- **三大范式**：1NF 字段原子不可再拆；2NF 非主键列完全依赖主键（消除部分依赖）；3NF 消除传递依赖（非主键不依赖其他非主键）。实际开发可适度反范式加冗余字段换性能。
- **主键设计**：自增 BIGINT id；外键尽量用逻辑关联（代码层维护）而非物理外键约束，便于扩展。
- **常用字段类型**：`BIGINT` 主键；`VARCHAR(n)` 短文本；`TEXT/LONGTEXT` 长文日记；`DATETIME/TIMESTAMP` 时间；`TINYINT` 状态/等级；`DECIMAL` 精确小数。
- **日期时间字段**：`create_time`、`update_time`，MyBatis-Plus 可自动填充。
- **软删除**：加 `deleted TINYINT`（0正常1删除），查询带 `deleted=0`，保留数据可追溯。

### 5. 其他高频小题
- **SQL 注入**：拼接字符串动态 SQL 导致；`#{}` 预编译参数化查询防注入，`${}` 直接拼接有风险（排序字段等无法参数化时才用并严格白名单）。
- **`#{} vs ${}`**：`#{}` 生成 `?` 占位符、安全；`${}` 直接替换文本、有注入风险。
- **分页**：`LIMIT pageSize OFFSET offset`；深分页可优化（记住 id 游标，了解）。
- **NULL 查询**：`IS NULL / IS NOT NULL`，不能用 `= NULL`。
- **COUNT(*)` vs `COUNT(列)`**：前者统计行数（含 NULL 行）；后者忽略该列为 NULL 的行。
- **唯一约束 / 非空约束 / 默认值**：表级保证数据完整性。

## 四、前端：JS ES6 + Vue3 + HTML/CSS ⭐

### 1. JavaScript ES6+ ⭐
- **`let/const` vs `var`**：`var` 函数作用域、有变量提升、可重复声明；`let` 块级作用域、不可重复声明；`const` 声明后不可重新赋值（对象内部属性可改）。
- **箭头函数** `() => {}`：简写、不绑定自己的 `this`（this 继承外层），适合回调；不能当构造函数。
- **解构赋值**：`const { id, name } = obj`；数组 `const [a, b] = arr`。
- **模板字符串**：`` `你好，${name}` ``，可换行、插值。
- **展开运算符 `...`**：拷贝/合并数组对象 `const b = {...a}`、函数可变参数。
- **异步处理**：
  - `Promise` 三种状态：pending（进行中）、fulfilled（成功）、rejected（失败）；`.then/.catch`。
  - `async/await`：同步写法处理异步，`await` 只能用在 async 函数内；请求失败要 try-catch。
- **数组常用方法**：`map`（映射新数组）、`filter`（过滤）、`find`（找第一个）、`forEach`（遍历无返回）、`reduce`（累加）、`includes/some/every`。
- **对象遍历**：`Object.keys/values/entries`；`JSON.parse()` / `JSON.stringify()`。
- **类型判断**：`typeof`（基本类型，难判 null/数组）；`Array.isArray()`；`instanceof`。
- **== vs ===**：`==` 会隐式转换；`===` 严格比较类型和值（推荐）。
- **事件冒泡/委托**（了解）：事件从目标向上冒泡；委托利用冒泡把子元素事件绑定到父元素。

### 2. Vue3 核心 ⭐
- **响应式**：
  - `ref(基本类型)`：模板里直接用，JS 中取值要 `.value`；
  - `reactive(对象/数组)`：整体响应式，不用 `.value`；
  - `computed` 计算属性：有缓存、依赖变化才重算，区别于 method。
- **生命周期（最常用 onMounted）**：`onBeforeMount → onMounted（DOM 挂载完，发请求）→ onUpdated → onBeforeUnmount → onUnmounted（清理定时器/图表实例/监听）`。
- **常用指令**：
  - `v-bind:` 简写 `:`：动态绑定属性；
  - `v-on:` 简写 `@`：绑定事件；
  - `v-model`：表单双向绑定；
  - `v-for`：循环渲染，**必须加 `:key`（唯一稳定值，别用 index 当 key 改顺序的列表）**；
  - `v-if` vs `v-show`：v-if 条件为 false 直接不渲染（销毁/重建、适合少切换）；v-show 切 CSS display（适合频繁切换）；
  - `v-html` 输出 HTML（注意 XSS）。
- **组件通信**：
  - 父传子：`props` 声明接收；
  - 子传父：`emit('事件名', 值)`，父组件 `@事件名`；
  - 跨层：provide/inject；全局共享用 Pinia。
- **axios 请求**：封装统一实例，请求拦截器自动带 token，响应拦截器统一处理 401 跳登录和错误提示；GET 用 params、POST/PUT 用 data/body。
- **路由 vue-router**：`/login` 等路径配置；**路由守卫 `beforeEach`** 判断未登录跳转登录页；动态路由、路由参数 `useRoute().params`。
- **Pinia 状态管理**：存登录用户信息、token、主题；`defineStore`，state/getters/actions；解决多组件共享状态。
- **组合式 API setup**：逻辑按功能聚合；`watch/watchEffect` 监听数据变化；`ref/reactive`。
- **组件定义三部分**：template（结构）、script（逻辑）、style（样式，可 scoped 只作用本组件）。

### 3. HTML / CSS 基础 ⭐
- **盒模型**：`width/height` 只算 content；总宽 = content + padding + border + margin；`box-sizing: border-box` 让 padding/border 计入设定宽度（布局更省心）。
- **块级 vs 行内元素**：块级 div/p/h1 独占一行、可设宽高；行内 span/a/图片设置宽高受限，行内块 img/inline-block 可设尺寸且不换行。
- **Flex 布局（必背常用属性）**：`display:flex`；`justify-content` 主轴对齐（flex-start/center/space-between）；`align-items` 交叉轴对齐；`flex-direction` 方向；`gap` 间距。
- **定位 position**：static 默认、relative 相对自身偏移不脱流、absolute 相对最近定位祖先脱流、fixed 相对视口固定。
- **选择器优先级**：`!important` > 内联 style > id(#) > class/属性/伪类(.) > 元素标签 > 继承；同级后写覆盖先写。
- **响应式**：`@media (max-width:768px){...}` 断点；百分比/vw 相对单位；rem 根字号。
- **语义化标签**：header/nav/main/section/article/footer，利于 SEO 和可读性。
- **常见居中方案**：Flex 居中 `justify-content:center; align-items:center`；文字水平 `text-align:center`。

## 五、工具与开发流程（JD 明确要求）⭐

### 1. Git ⭐（命令要会说/会用）
- **三个区域**：工作区 → 暂存区(stage) → 本地仓库 → 远程仓库。
- **基础流程**：
  ```bash
  git status                 # 查看改动
  git add .                  # 全部加入暂存
  git commit -m "feat: 新增日记新增接口"
  git push                   # 推送到远程
  git pull                   # 拉取并合并远程更新
  ```
- **分支**：`git branch` 查看；`git checkout -b dev` 新建并切换；`git checkout main` 切回；`git merge dev` 合并；`git branch -d dev` 删除。
- **查看历史**：`git log --oneline`；回退 `git reset --hard 版本号`（谨慎）。
- **冲突解决**：pull/merge 冲突时手动编辑保留代码 → add → commit；提交前先 pull 保持同步。
- **.gitignore**：忽略 node_modules、target、本地配置文件不上传。
- **提交信息规范**：`feat`新功能 / `fix`修复 / `docs`文档 / `style`样式 / `refactor`重构 / `chore`构建。

### 2. Maven（Java 后端构建工具）⭐
- **作用**：依赖管理（pom.xml 引依赖，自动下载 jar）+ 项目构建生命周期。
- **pom.xml 核心**：`groupId/artifactId/version`；`dependencies` 引入 Spring Boot Starter、MyBatis-Plus、MySQL Driver；`parent` 继承 spring-boot-starter-parent。
- **生命周期**：`compile` 编译 → `test` 测试 → `package` 打成 jar/war → `install` 装入本地仓库。
- **常用命令**：`mvn clean` 清 target；`mvn package -DskipTests` 打包跳过测试；`mvn install`。
- **仓库**：本地仓库 ~/.m2；中央仓库；私服（了解）。依赖版本由父 BOM 统一管理。

### 5. 流程与协作（JD：晨会、代码评审、迭代、文档、Bug 修复）
- **敏捷开发**：需求拆成迭代，每日晨会同步进度/阻塞，开发完提 PR/MR 经代码评审合并。
- **代码评审 Code Review**：检查命名、空指针、SQL 注入、越权、异常处理、重复代码。
- **Bug 排查思路（必背话术）**：先稳定复现 → 看前端控制台 Network 请求和返回 → 看后端日志/断点定位 → 缩小范围到某层 → 修改 → 回归测试 → 记录到笔记。
- **接口文档**：写清 URL、请求方式、入参（名/类型/必填/说明）、返回字段、示例；可用 Apifox/Postman 调通。
- **环境概念**：本地开发环境 dev、测试环境 test、生产环境 prod；配置分 `application.yml` + `application-local.yml`，密钥不提交 Git。
