# 绪见 · 部署说明

> 适用环境：Windows / Linux / macOS，需 JDK 17、MySQL 8.x、Node.js 18+

## 一、环境要求

| 组件 | 版本要求 | 用途 |
|---|---|---|
| JDK | 17+ | 后端编译与运行（低版本会报 UnsupportedClassVersionError） |
| MySQL | 8.0+ | 业务数据库（库名 `see_you`，utf8mb4） |
| Node.js | 18+ | 前端构建 |
| Maven | 3.8+（或直接用 IDEA 内置 Maven） | 后端打包 |

## 二、数据库初始化

1. 创建数据库：
   ```sql
   CREATE DATABASE see_you DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```
2. 按顺序执行 `see_you/sql/` 下的脚本：
   - `migration/` 目录：8 个增量迁移脚本（按文件名日期从旧到新执行）
   - 根目录 3 个初始化数据脚本：`add_60_scales_full.sql`（60 套心理量表）、
     `add_ai_keywords.sql`（AI 关键词话术）、`add_test_papers.sql`（试卷结构）
3. 建议补一个性能索引（已在本机库上建过）：
   ```sql
   ALTER TABLE psy_diary ADD INDEX idx_uid_date (user_id, diary_date);
   ```

> 完整的表结构说明见 `docs/数据库说明.md`。

## 三、后端启动

```bash
cd see_you
mvn package -DskipTests          # 打包（pom 已配置 spring-boot repackage，产出可执行 fat jar）
java -jar target/see_you-0.0.1-SNAPSHOT.jar --server.port=8081
```

> ⚠️ **打包后确认一下产物大小**：正常应是 **60MB 左右的可执行 fat jar**。
> 如果只有几百 KB，说明 repackage 没执行，`java -jar` 会报"没有主清单属性"。
> 常见原因是后端进程正占用 `target/*.jar` 导致无法重命名 —— 先停掉后端再打包。
>
> 答辩演示建议关闭限流，避免反复登录被 429 挡住：
> ```bash
> java -jar target/see_you-0.0.1-SNAPSHOT.jar --app.rate-limit.enabled=false
> ```

可配置项（环境变量或启动参数，均有本地默认值）：

| 配置 | 说明 | 默认值 |
|---|---|---|
| `DB_PASSWORD` | MySQL root 密码 | 本地开发值（见 application.yml） |
| `JWT_SECRET` | JWT 签名密钥（生产必改） | 内置开发密钥 |
| `AI_API_KEY` | 大模型 API Key | 内置开发 Key |
| `--app.dev-captcha-log=true` | 开发态：验证码答案打到日志、找回密码接口回显 devCode。**生产严禁开启** | 关闭 |
| `spring.mail.username` | 找回密码的发件邮箱，留空则邮件降级为日志 | 空 |

生产检查清单：
- [ ] 修改 `JWT_SECRET`（否则任何人可用默认密钥自签 token）
- [ ] 修改数据库密码，不给 `DB_PASSWORD` 默认值留后门
- [ ] 不开启 `--app.dev-captcha-log`
- [ ] `application.yml` 中 `mybatis-plus.configuration.log-impl: StdOutImpl` 建议注释掉（否则每条 SQL 打到控制台）

## 四、前端启动

```bash
cd frontend
npm install
npm run dev      # 开发模式 http://localhost:5173（vite.config.js 已代理 /api 到 8081）
npm run build    # 生产构建 → dist/
```

生产部署：把 `dist/` 交给任意静态服务器（Nginx / 服务器空间），并将 `/api`、`/upload`、`/ws` 反向代理到后端 8081 端口。Nginx 参考：

```nginx
server {
    listen 80;
    root /var/www/seeyou/dist;
    location /api/  { proxy_pass http://127.0.0.1:8081/; }
    location /upload/ { proxy_pass http://127.0.0.1:8081/upload/; }
    location /ws/   { proxy_pass http://127.0.0.1:8081/ws/; proxy_http_version 1.1;
                      proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade"; }
    location /      { try_files $uri $uri/ /index.html; }
}
```

## 五、生产部署（二选一）

### 5.1 Docker Compose 一键部署（推荐）

```bash
cp .env.example .env                 # 填入真实密码与密钥
docker compose -f deploy/docker-compose.yml up -d --build
```

包含三个服务：`mysql`、`backend`（8081）、`nginx`（80）。前后端**同域**，前端继续请求 `/api`、`/ws`，无需改任何前端代码。

上传文件通过共享卷打通：后端写入 `/app/frontend-public/banner|cover|avatar...`，Nginx 从同一个卷直接吐出去。

> ⚠️ 数据库初始化**不自动化**：迁移脚本必须按日期顺序执行，容器化自动导入容易顺序错乱。
> 首次启动后按第二节手动导入 SQL。

### 5.2 裸机部署（无 Docker）

```bash
bash deploy/deploy.sh build      # 构建前端 dist 与后端 jar
sudo bash deploy/deploy.sh install   # 部署到 /opt/seeyou 并注册 systemd 服务
sudo cp deploy/nginx-standalone.conf /etc/nginx/conf.d/seeyou.conf
sudo nginx -t && sudo systemctl reload nginx
```

安装后务必编辑 `/opt/seeyou/backend/backend.env` 填入真实 `JWT_SECRET`、`DB_PASSWORD`、`AI_API_KEY`。

### 5.3 上线前安全清单

- [ ] `JWT_SECRET` 换成 32 位以上随机字符串（**默认密钥等于任何人可自签 token 冒充任意用户**）
- [ ] 数据库密码改成强密码，不要沿用开发环境的弱密码
- [ ] 确认 `--app.dev-captcha-log` 未开启（生产开启会把验证码答案打进日志）
- [ ] 启动时带 `--spring.profiles.active=prod`（自动关闭 SQL 日志）
- [ ] `application-local.yml` 已加入 `.gitignore`，未随仓库外传
- [ ] 若仓库曾经公开，**先轮换密钥再上线**（见下节）

### 5.4 密钥泄露应急处理

本仓库历史提交中曾包含明文密钥（`application.yml` 里的 DB 密码与 AI Key）。清理工作树**不会**清除 Git 历史，若该仓库已经推送到公开平台（Gitee / GitHub），请按以下顺序处理：

1. **立刻轮换**：重新生成 DeepSeek API Key、修改数据库密码、更换 `JWT_SECRET`
2. 把新值放进 `application-local.yml`（已被忽略）或环境变量，**不要再写进 `application.yml`**
3. 如必须彻底清除历史：改用新仓库推送当前工作树，或用 `git filter-repo` 重写历史后强推（会改变所有 commit hash）

## 七、常见问题

1. **页面表现与代码不符**：项目路径含中文，Vite watcher 可能失效。结束 dev 进程 → 删 `node_modules/.vite` → 重启。
2. **验证码看不到答案**：正常现象。开发时用 `--app.dev-captcha-log=true` 启动，后端日志会打印 `[Captcha] key=... code=...`。
3. **AI 陪伴无响应**：检查 `AI_API_KEY` 是否有效；后端已设 5s 连接 / 30s 读取超时，超时会有友好提示而不是挂死。
