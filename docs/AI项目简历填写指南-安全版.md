# AI 生成项目 · 简历安全填写指南（绪见专用）

> 核心一句话：**简历只写"客观存在的功能 + 用到的技术"，不写"你亲手造出来的能力背书"；定位成"个人学习/练手项目"，不吹成独立产品或商业项目。**
> 目标：简历上的每一句话，你都能用自己的话讲 20~30 秒；讲不清的句子，宁可删。

---

## 一、先记住 3 条填写原则（不翻车的底层逻辑）

### 原则1：客观功能可以写，能力来源不要吹
- **可以写**：这个项目里有登录功能、日记增删改查、ECharts 图表、用了 JWT、用了 MySQL 表——这些是代码里的事实，不丢人。
- **不要写**：不要写"我独立设计了整套架构""我优化了性能提升 X%""我训练了情绪预测模型""我自研了实时推送"——这些是能力背书，AI 产物你讲不出过程，一问就穿。

### 原则2：项目定位写"学习练手项目"，降低面试官对深度的预期
- 角色/类型写：**个人全栈练习项目（前后端 + 数据库）**。
- 不要写："独立产品""上线系统""主导开发""企业级架构"。
- 面试官对练手项目的预期本来就是"看得懂、能跑、基础概念对"，不会按正式项目深挖；预期放低，你就不容易崩。

### 原则3：每条 bullet 必须配一个"最低掌握度"，达不到就删
- 下面第四节有逐句对照表：先看句子后面要求你会什么，**做不到就把这条删掉或换成更浅的说法**，不要硬写。

## 二、选词安全词库（照着选动词和形容词）

### ✅ 放心用（中性、客观、AI辅助也成立）
| 类型 | 可用措辞 |
|---|---|
| 项目定位 | 个人练习项目 / 全栈练手项目 / 学习项目 |
| 动词 | 使用、基于、完成、实现了【某功能】、对接、调用、封装了【工具函数/请求实例】、接入、展示、提交（Git）、调试、联调 |
| 技术描述 | 基于 Spring Boot 实现…、使用 Vue3 完成页面开发、采用 JWT 做登录鉴权、使用 ECharts 渲染图表 |
| 程度词 | 熟悉（讲得出作用）、了解（知道大概）；**不要用"精通、熟练掌握、深入"** |

### ⚠️ 先学会再写（有门槛，不懂就降级或删除）
| 慎用措辞 | 前提条件（满足再写） | 不满足时的降级说法 |
|---|---|---|
| 设计了数据库表 | 能说出3张表的字段和关联关系 | "使用 MySQL 存储用户、日记等数据" |
| 建立联合索引优化查询 | 能解释最左前缀和为什么这么建 | 删除优化表述，只写"数据存储于 MySQL" |
| 封装 Axios 拦截器 | 能讲清请求/响应拦截器各做什么 | "使用 Axios 调用后端接口" |
| 实现登录鉴权（JWT） | 能讲完登录→签发token→携带→校验流程 | "使用 JWT 完成登录状态保持" |
| 防止越权 | 能解释 userId 为什么从 token 取 | 删除，不写 |
| 单元测试 | 真的打开过测试类、能说出测了什么 | 整句删除 |

### ❌ 坚决不写（AI产物 + 你不懂 = 高危）
- ❌ KNN / AR 模型、算法训练、模型评估、预测准确率
- ❌ WebSocket 实时推送的实现细节、高并发、性能调优、QPS
- ❌ Docker / docker-compose / 线上部署、Linux 运维细节
- ❌ 量化结果："响应从 700ms 降到 25ms""支撑 X 用户""100 个测试"
- ❌ 微服务、分布式、消息队列、Redis（项目里没有就不写）
- ❌ "独立开发 / 主导 / 从零搭建整套架构"这类暗示全部手写的词

## 三、绪见项目 · 简历安全填写版（保守措辞，直接用）

```
2026.08 - 至今    绪见 · 个人情绪记录与可视化平台    个人全栈练习项目
技术栈：Spring Boot · MyBatis-Plus · MySQL · Vue3 · Pinia · ECharts · Axios · Git

• 基于 Spring Boot + MyBatis-Plus + MySQL 搭建后端，实现用户登录、情绪日记
  新增/编辑/删除/分页列表等基础接口，使用统一返回格式。
• 使用 JWT 完成登录状态保持：登录后返回 token，前端请求携带，后端校验登录状态。
• 使用 MySQL 存储用户信息、情绪日记、预警记录三类数据；后端按 Controller、
  Service、Mapper 三层组织代码。
• 前端使用 Vue3 + Pinia + Vue Router 完成情绪记录与统计页面开发，使用 Axios
  调用后端接口并统一处理请求与错误提示。
• 使用 ECharts 渲染情绪趋势折线图和情绪分布图等常见图表，完成页面响应式展示。
• 使用 Git 进行代码提交与版本管理。
```

### 这版和上一版的区别（为什么更适合AI项目）
1. 删掉了"联合索引优化、BCrypt、防越权、三级预警规则设计、性能/测试/深色模式工程化"等深词，只保留你低成本就能讲清的主干。
2. 措辞全部客观化："使用/基于/实现了某功能"，没有"设计、优化、自研"。
3. 技术版本号（3、8、6）可省略，只写技术名，减少被追问版本细节的机会。
4. 只写6条以内，宁少勿多——写3条能讲透，胜过写8条被问穿。

### 可选项：只有真的补懂了才加回去
- [ ] BCrypt 密码加密（能讲"不存明文、加密比对"即可加）
- [ ] Axios 拦截器（能讲"统一带token、统一跳登录"即可加）
- [ ] 三级情绪预警（能讲清规则分级即可加，不要讲算法）
- [ ] 项目演示/GitHub 仓库链接（跑通并提交后加在简历顶部）

## 五、让这份简历"站得住"的 5 个低成本动作（建议2天内做完）

不用重写项目，只要做到下面 5 件事，简历就不是空中楼阁：

1. **本地完整跑通一次**（必做）
   - 后端启动不报错、前端能打开；完成"注册/登录 → 新增一条情绪日记 → 列表显示 → 看到一张图表"。
   - 能口述启动步骤：建库导 SQL → 后端 IDEA 启动（端口8081）→ 前端 npm install、npm run dev（5173）。

2. **对着安全版简历，把第四节对照表的7条最低答法背熟**
   - 每条能口头说2~3句，不需要写代码。

3. **打开并看懂3个文件/类（不要求改，能指认）**
   - `PsyDiaryController.java`（日记接口在哪）；
   - `sys_user` / `psy_diary` 对应的实体类或建表 SQL（字段是什么）；
   - 前端 `src/api` 里的请求封装文件（请求怎么发出去的）。
   - 面试可说："我把核心链路的代码逐段看过、改过小问题。"

4. **亲手改1个小功能（最有说服力的"我参与过"证据）**
   - 选最简单的：把某个图表标题改个文字、给日记加一个备注字段并跑通、改一个按钮颜色；改完能说"我调整过XX"。
   - 这比任何简历措辞都能证明你不是只点了生成按钮。

5. **代码推送到 Git 仓库（可选但强烈建议）**
   - 简历放 GitHub/Gitee 链接；README 写技术栈、功能列表、启动步骤、2~3张截图。JD 明确写了"有 GitHub 项目加分"。

## 六、被问"这个项目是不是 AI 做的 / 哪部分你自己做的"——统一口径（不撒谎、不甩锅）

### 标准回答（背熟，温和、真实、有边界）
> "这是我用来练全栈开发的个人学习项目，开发过程中用 AI 辅助生成了部分样板代码来提效；**登录流程、日记增删改查这些核心接口的调用链路、数据库表结构和前后端联调是我自己梳理、调试和修改过的**；像算法预测那部分我主要了解它的使用和展示，底层实现还在学习。"

### 分场景补句
- **被问"你具体做了什么"**："我负责把项目跑通、梳理核心业务流程、理解每个接口的入参出参、做过小功能调整和联调；也对照代码补了 SpringBoot、SQL、Vue 的基础。"
- **被问"最难的问题"**：说你真改过的那1个小问题（第五节第4条），讲清"现象—怎么定位—怎么改—结果"，不要讲架构级难题。
- **被问到不懂的模块**："了解作用，细节不深，正在补"，不装懂。

> 注意：不要主动提 AI；不否认、不吹嘘，把重点放在"我梳理、调试、联调、补基础"这些你真做了的动作上。
