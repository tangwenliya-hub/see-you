> ✅ **状态：已实施**，代码在仓库根目录 `miniapp/`，说明见 `miniapp/README.md`。
> 本文保留作为选型与范围决策的留档。

> 定位：**只用于开发与答辩演示，不上线、不审核、不备案**。
> 结论先行：uni-app + Vue3 新起 `miniapp/` 目录，只做 5 个核心页，后端零改动，现有 H5 零改动。

## 1. 演示环境前提（已确认，成本≈0）

| 事项 | 结论 |
|---|---|
| 发布/审核/ICP 备案 | ❌ 全部不需要，开发者工具模拟器演示即可 |
| "不校验合法域名、web-view、TLS、HTTPS 证书" | ✅ 开发者工具里勾选，直连 `http://localhost:8081` |
| 小程序账号 | 个人主体免费注册即可；**答辩前可先用"测试号"**（工具内一键申请，连注册都省） |

| 后端 | SpringBoot 照常启动，需过一遍写死 `localhost` 的 CORS/上传路径配置 |

## 2. 技术选型

**uni-app + Vue3 + Vite**（HBuilderX 或 CLI 均可）。

理由：
- 语法与现有 frontend（Vue3 SFC + `<script setup>`）一致，迁移认知成本最低
- api 层适配后，171 个接口函数直接复用
- 现有 Element Plus 无法在小程序使用，uni-ui / 原生组件替代
- 不选原生小程序：wxml/wxss 与现有代码风格割裂，复用率更低

不选的路线（留档）：
- **全量迁移 12 页**：15,000 行重写，性价比最低
- **web-view 套壳**：需要备案域名，且体验与现有 H5 无差别，无增量价值

## 3. 目录结构与复用策略

```
绪见/
├── frontend/          # 现有 Vue3 H5，一行不动
├── see_you/           # 现有 SpringBoot 后端，一行不动
└── miniapp/           # 新增 uni-app 工程
    ├── src/
    │   ├── pages/           # 只建 5 个页（见 §4）
    │   ├── api/
    │   │   ├── adapter.js   # ★ 核心：平台无关请求适配层
    │   │   ├── index.js     # 从 frontend/src/api/index.js 复制，171 函数签名不变
    │   │   └── sense.js     # 同上复制
    │   ├── utils/
    │   │   └── storage.js   # uni.getStorageSync 封装（对应 168 处 localStorage）
    │   └── stores/user.js   # Pinia（uni-app Vue3 支持）
    └── pages.json           # 对应现有 35 条路由里的 6~7 条
```

**adapter.js 设计**（关键动作，先做）：
把"发请求"抽象成两个实现，接口定义层完全平台无关：
- H5/浏览器实现 → axios（现成逻辑）
- 小程序实现 → `uni.request` 包装出相同签名（含 Bearer token 注入、`res.data` 解包、401 清会话跳登录）

收益：即使最终不做小程序，这层重构对现有项目也是中性优化；做了，则 api 层复用率 95%。

## 4. 页面清单（5 页 + 1 弹层）

| 页面 | 对应现有页面 | 说明 |
|---|---|---|
| `pages/login/login` | Login.vue | 账号密码 + 图形验证码（/auth/captcha），单列布局 |
| `pages/main/main` | Main.vue | 精简为今日情绪入口 + 功能九宫格，砍掉 PC 装饰层 |
| `pages/diary/diary` | Diary.vue | 列表 + 详情，砍富文本装饰 |
| `pages/diary/write` | WriteDiary.vue | 文本 + 情绪选择 + 强度，核心录入路径 |
| `pages/assistant/assistant` | Assistant.vue | 会话列表 + 对话；无 SSE，普通 POST 即可，无额外坑 |
| `pages/profile/profile` | Profile.vue（极简） | 头像昵称 + 统计概览 + 退出；含**非医疗免责声明** |

tabBar 4 项：主页 / 日记 / AI / 我的（写日记从主页和日记页入口进，不占 tab）。

**明确不做**：FM（audio 需换 InnerAudioContext）、量表 Test、数据看板（ec-canvas + 词云成本高）、Classroom、Feedback、全部 admin 15 页（WebSocket 通知无意义）、无感记录 senseTracker（依赖 document click 监听，小程序无 DOM，0% 可复用——论文里该模块只讲 H5 实现）。

## 5. 答辩演示动线（建议脚本）

1. PC 端：登录 → 写一篇日记 → 展示数据看板
2. 手机 H5：扫码同一账号 → 渐进式响应式（创新点三）
3. **小程序：开发者工具模拟器登录同一账号 → 同一条日记可见 → 写日记 → AI 对话 → 收到情绪预警卡片**
4. 收尾话术："一套后端服务三端，小程序端复用全部 REST 接口，客户端按场景裁剪"——比"一套代码全端"更真实也更好答

## 6. 已知风险与对策

| 风险 | 对策 |
|---|---|
| WXSS 不支持 `*`/标签选择器 | 不搬 mobile.css，每页按小程序规范重写样式 |
| 演示当天现场断网/防火墙拦 8081 | 提前关掉电脑防火墙对 8081 的拦截；备用方案：手机热点 + 真机预览 |
| 词云/图表缺失被追问 | 话术：小程序端定位"轻记录"，重图表在 H5/PC 端，属有意裁剪 |
| 论文叙事 | 创新点三改写为"H5 渐进响应式 + 小程序端核心场景重构"，面试小抄同步更新 |
| 个人号类目 | 若日后真要上线：选"工具-效率"类目，避免"医疗健康"，三级页挂免责声明 |
